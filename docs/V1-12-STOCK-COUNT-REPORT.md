## 数量与版本证据

| 业务动作 | 真正发生数量动作的位置 | 同事务版本 |
| --- | --- | --- |
| 入库 | 目标物理库位 | 桶、SKU、库位 |
| 出库 | 源物理库位 | 桶、SKU、库位 |
| 移库发出 | 源及系统 Transit | 两腿各自的桶、SKU、库位 |
| 部分接收 | Transit 及固化目标 | 两腿各自的桶、SKU、库位 |
| 剩余返源 | Transit 及原源 | 两腿各自的桶、SKU、库位 |
| 盘点调整 | 实际有差异的桶 | 桶、SKU、库位，同范围可合并一次 |
| 无差异、草稿、查询、批次建档、失败、成功重放 | 无数量动作 | 不推进 |

版本计数器与余额独立，属于明确 generation；NO_BATCH 使用非空内部身份键。
归零桶保留历史。以有效 SLE/Bundle 身份与精确数量摘要诊断连续性，忽略纯估值和 modified。
摘要不替代计数器。共享守卫内采用当前读；原生结果、轻量日志、任务、请求和版本单次提交。

原生适配使用 Stock Reconciliation。合成混合行验证账面 8、实盘 5 的 -8/+5 两条 SLE，
账面 10、实盘 12 的 -10/+12，以及账面 5、实盘 0 的净 -5。零账面盘盈使用原生正向 SLE；
小数 1.125 无损核对。每个批次独立净额，不能抵消为 SKU 汇总。
锁定控制器会为明确实盘零留下零 Inward 草稿 Bundle，适配器单独核验它未提交且不对应有效 SLE。
无差异完成创建日志及请求，quantity_effect=None，无原生单据、Bundle、SLE 或数量版本变化。

原生 helper 的类型权限通过 Frappe Custom DocPerm 提供；没有原生创建、提交、取消或删除授权。
受管 Item 详情/列表、原生生命周期及 HTTP 白名单独立保护。合成员工以自身身份执行，未切换 Administrator。
