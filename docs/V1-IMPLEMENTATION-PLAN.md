## 3. 库存内核设计基线

### 多行单据、日志与请求

业务单头保存稳定单据 ID、类型、状态、提交版本，行保存不可重用的行 ID、SKU、位置、批次选择和 Decimal 数量。一次受控动作可生成一张或多张原生单据。先验证原生字段及明细约束，必要时按位置或腿拆分；整个动作只有一个提交边界。同桶多行保留各自业务行身份，校验时合计其需求，避免分别通过后超扣。

轻量日志采用操作头和关联行。头保存动作、操作者、服务端时间、业务单号、请求记录引用、原因和原操作引用。关联行保存业务行、角色（原行、入账、发出、接收、退回或补偿）、原生 DocType/单据/行引用；允许一个业务行因多腿或后续多次接收关联多个原生行。多行合并时必须能从原生记录精确复核每行，无法区分则采用保留行身份的提交方式。数量、批次及余额沿原生单据、有效 SLE 和 Bundle 取得。日志与关联追加写入，审批决策和产品属性修改各有独立的历史。

请求表通过数据库唯一约束覆盖 `(site 内组织, 认证主体, 命令, 幂等键)`，保存规范化负载摘要、业务单号、结果引用及完成状态。摘要包含目标对象及版本、稳定行 ID、规范化批次、精度后等值数量和业务原因等有语义字段。同键同摘要在当前授权下重放原结果；同键异摘要拒绝。业务单状态、原行更正额度/唯一绑定及移库行剩余量约束跨键重复，期初另设导入标识与分组唯一键。失败事务可用原键重试；提交结果不明时先按键读取已提交状态。正式保留期由 B08 确认，过期后仍保留生效唯一性依据。

### 数量、批次和事务

- 业务 API 用十进制字符串传数量，应用用 Decimal 校验有限值、符号、单位精度和上限。原生数量事实按 Decimal/Numeric 精度验收，V1-07 的业务单据行可保存经验证且可无损往返的规范十进制文本。超精度明确拒绝；整数、小数、零盘点及极限值以数据库和原生引擎往返实测为准。关闭自动批次分配和负库存，底层数值类型和舍入不满足精确对账时暂停正式库存发布。
- 批次三态为 `BATCH`、`NO_BATCH` 和未选择。已测候选为裁掉首尾 Unicode 空白，保留原始文本、大小写、内部空白和全半角。空值、全空白、疑似空引号单独处理，保留前缀及无效字符拒绝；长度上限和历史例外走 B03。映射以稳定 SKU + 种类 + 规范键为唯一维度，无批次键用固定非空哨兵处理数据库唯一性；真实批次比较规则须在数据库排序规则下验证。各 SKU 有独立系统 Batch，原生 ID、前缀和映射只在适配层使用。
- V1 先验证组织级事务锁串行化受控数量写入，覆盖空桶、跨单据竞争、相反行序和盘点范围新增桶。固定顺序为组织守卫 → 幂等记录 → 业务单/盘点/原移库或纠错行（稳定 ID 排序）→ 适配层必要资源（按稳定 SKU、库位、批次排序）→ 原生提交 → 日志/状态/版本更新 → 提交。所有受控路径与经批准会影响数量的维护共用规则，无法共用锁的维护先停写排空。对受保护数量和状态使用当前读；在生产候选隔离级别实测等待锁前已有读、原生内部读和死锁回滚，确认读取的是正确提交版本。评估更细锁须另证空桶与范围版本安全。
- 一次命令在同一事务提交原生单据、有效 SLE/Bundle、Bin、业务状态、版本、日志和请求记录；内部路径禁止提前提交。一次拒绝或故障时由新连接核对零残留，避免把缓存或复用单号当作持久化证据。死锁等瞬时失败整体回滚后按原键重新执行完整校验。报告、通知等外部副作用在提交后执行。
- 员工角色通过 Haxpower API 及服务端仓库范围校验。原生提交使用最小权限、受约束的服务上下文，记录认证员工为业务操作者。Hooks 限制受管 SKU 其它写入口、原生取消、账簿重建和清理；管理员、服务器代码、队列、调度和 DBA 依独立权限与运维记录治理。异常差异阻断受影响范围并保留证据。

### 盘点、移库与纠错

移库发出锁定源、目标及各行的在途归属；接收按原发出行及批次保留原生关联。逐行应满足 `已发 = 已收 + 已退 + 在途`。退回仅处理剩余在途，追加返源单并关掉对应接收额度；已接收部分或有下游消耗的反向业务进入人工审核，规则见 B07。

盘点截止版本采用轻量计数器提案。任务记录受管库位范围版本及逐桶版本、账面数量、截止时点和范围。所有数量写入在同事务推进受影响的桶和库位范围版本，以识别净量相同的往返和范围新桶。提交或审批生效前持相同组织锁重验授权、版本及桶，旧任务拒绝并重建盘点快照；无差异确认也记录动作并结束任务。升级回填从通过原生对账的受保护快照建立版本代次，切换前未完成且无法证明版本连续的任务作过期处理，需人工重开。禁止沿旧版本补录穿过有效盘点截止；B05 已于 2026-11-25 批准非冻结、LOCATION/SKU/BUCKET、版本过期重盘和授权发现零基线新桶。补录及关闭期间由 B12 确认，审批策略由 B06/V1-13 接入。

入库纠错对原桶新增出库，出库纠错对原桶新增入库，盘点按原调整净差额反向记账。正式更正应有原因、审核、原操作及原行，重验权限、有效历史、可用量和下游依赖。无法安全确定补偿时保留审核记录，并拒绝数量变更。原事件已完成的在途关闭和重放必须一致。后台正常重估可更改技术元数据；验收对比数量事实、归属和关系。

### 对账和升级

按公司、SKU、叶库位、域批次及在途来源核对原生单据行、有效 SLE 和已提交 Bundle，聚合逐桶净变动与标准批次余额，再按 SKU/叶库位核对 Bin。期初已入账时只汇总一次。盘点同一单行可能有多条 SLE，按真实净变动核对。受控操作逐行动作检查原生引用和日志覆盖，另查孤立单据、孤立日志、缺失 Bundle、重复纠错、意外取消及映射冲突。计量用 Decimal 精确比较。升级前后保存脱敏对账摘要并复跑权限和数量回归；验证未完移库、旧盘点、既有幂等键、调整关系、私有附件、正常重估及关账时点语义。从相同恢复点还原 DB、站点文件和配置后重核，放行前复核持久队列与待处理任务。
