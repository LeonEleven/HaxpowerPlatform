# V1 技术决策草案

状态为待审查。拟议采用 **Frappe Framework + 独立库存 App**，保留 ERPNext + 独立 App 为可选方案。本草案不改变现有项目决策。
[决策记录](DECISIONS.md) · [技术路线比较](TECHNICAL-ROUTE-COMPARISON.md)

## 拟议理由

- 当前 PRD 以数量、批次、权限和审计为主，采购、销售、财务与估值均留待后续。Frappe-only 的真实 NULL、同事务库存事件、分次接收和库存版本已在隔离库验证。
- ERPNext 可复用的 Stock Entry、在途累计、原生报表及估值机制具有价值。V1 若长期只管理数量，需要权衡无批次适配、双账、原生权限与后台作业的持续维护成本。
- Frappe-only 承担自建库存规则、报表和运维的长期责任。单账的优势依赖于所有库存变更都通过业务 API、生效事务和追加事件。
[Stage 2A 实测](STAGE2A-FRAPPE-ONLY-SPIKE-REPORT.md) · [Stage 1F 实测](STAGE1F-AUDIT-COUNT-REPORT.md)

## 待批准的条件

1. **V1 范围。** 确认数量优先，库存价值和 ERP 标准采购、销售、财务仍处于后续范围。若近期要上，以新的需求重新比较路线。
2. **盘点。** 选择冻结，或采用服务端库存版本并明确过期任务如何重盘、多桶截止和无差异确认。
3. **纠错。** 明确部分接收后如何退回在途余量，完成移库后出现下游消耗时如何记录补偿、授权和审批，以及批次不足时的处理原则。
4. **批次与仓库。** 确认批次大小写、空格及历史归档规则，决定同一仓库内不同库位是否始终两阶段。确认 ALL/SELECTED/NONE 和新增仓库的默认授权。
5. **上线保障。** 确认期初库存切换和验收、全部查询/报表/导出与附件边界、不可篡改审计要求、恢复目标、恢复演练及责任人。

路线获批后仍需按风险优先安排生产级验收。架构选择、业务规则与启动开发由独立评审记录。
