# ERPNext 第一轮最小验证计划

日期：2026-11-17。依据：[ERPNext-FIT-GAP](ERPNext-FIT-GAP.md)、[库存模型](INVENTORY-MODEL.md)、[权限](PERMISSIONS.md)、[业务流程](BUSINESS-FLOWS.md)、[API 契约](API-CONTRACTS.md)、AGENTS.md。

状态：**计划，全部待执行**。本次不创建站点、数据或 App。版本与环境方案见 [环境报告](ENVIRONMENT-REPORT.md)。

## 1. 目标与执行约束

验证同一 SKU 的真实批次与领域无批次能否在不修改 ERPNext/Frappe 核心、不直接写库存底表的前提下，完整完成入库、精确出库、两阶段移库、部分接收、盘点与权限控制；同时测量 ERPNext 估值对只管数量的影响。

先记录原生行为，再在独立 `haxpower_platform` 原型 App 内验证最小适配。每个结果标注“原生通过 / 适配后通过 / 失败 / 阻塞 / 未执行”，不能把文档推断写成通过。允许的差距解决手段仅为受支持接口、配置、Hooks 和独立 App，不改既有业务规则。

正式库存提交必须事务一致，任何失败均不改变单据生效状态、流水和余额。禁止负库存；数量按 Decimal 对账；正式流水保留审计链。权限测试使用非管理员账号，不用 Administrator 的结果代替普通用户测试。

## 2. 最小数据与隔离方法

仅使用虚构数据；一套独立验证站点和数据库，统一时区 Asia/Shanghai，记录审批开关状态（基础轮关闭，确认不会跳过移库两阶段）。按用例组建立新的测试数据或保留组级基线，避免后一个用例沿用前一个用例已扣减的库存。需要重置时用正式冲销/调整，或下一轮另建隔离站点；不直接删除正式流水或修改余额。

| 对象 | 最小数据 |
| --- | --- |
| 产品规格 | SPEC-01 喷油嘴、SPEC-02 活塞环 |
| 品牌/SKU | SKU-A：SPEC-01/品牌甲；SKU-B：SPEC-01/品牌乙；SKU-C：SPEC-02/品牌甲 |
| 单位 | SKU-A/B 使用 PC（0 位）；SKU-C 为精度验证另设允许小数的测试单位，3 位 |
| 仓库/库位 | W1、W2，各有 L1/L2；系统 TRANSIT 独立于普通可用库存；另建 W3 后再新增 W4 验证动态权限 |
| SKU-A 初始库存 | W1/L1：STD61=12、STD62=20、无批次=15；W1/L2：无批次=12；W2 初始为 0 |
| SKU-B 初始库存 | W1/L1：STD61=7，证明不同 SKU 可使用同样的显示批次文本，库存仍独立 |
| 用户 | U-ALL、U-W1（SELECTED=W1）、U-BOTH（SELECTED=W1/W2）、U-NONE、U-EMPTY（SELECTED 空列表）、U-QUERY（只有查询操作权限） |

U-ALL 与 SELECTED/NONE 测试用户尽可能配置相同操作角色，以单独比较仓库范围；另给 U-W1 叠加角色验证多角色不扩大仓库范围。移库正常操作由有源/目标双权限的 U-BOTH 执行。

若采用特殊 Batch 候选方案，内部 ID 必须按 SKU 唯一、保留命名空间并防止用户冲突；不能假设所有 SKU 共用一个 `__NO_BATCH__` 主键。对外始终返回 `batch = null`，出库/移库/盘点输入明确 `NO_BATCH`。无此模式或字段缺失表示未选择；不能默认变成无批次。此映射是待验证方案，不是最终决策。

| 入口 | 必测行为 |

| 库存流水、批次详情、单据详情 | 猜测未授权 ID、跨仓库关联、父 Warehouse 下含未授权叶节点 |
| Stock Balance、Stock Ledger、批次报表 | 无筛选/伪造过滤条件；如异步 Prepared Report 可用，检查其缓存及下载权限 |
| Excel/CSV 导出、附件 | 直接访问导出/文件 URL 及未授权单据附件；不能只保护页面入口 |
| 自定义 API、标准 REST/可调用方法 | 正常与绕过 facade 的直接访问均测试；无需求的原生入口收紧权限，不能假设知道 URL 才安全 |

## 5. 库存估值验证矩阵（E14）

在独立测试公司/数据组中使用受支持设置测试；不把“隐藏财务模块”当成卸载 ERPNext 的会计依赖，也不直接修改底层账表。不同设置使用新测试数据，避免在已有流水公司上强行切换受保护设置。

| 场景 | 操作与观察 |
| --- | --- |
| 数量最小配置 | 记录 Company、Warehouse、Item 必需的币种、科目、成本中心、估值方法；能否仅用 Material Receipt/Issue/Transfer、Stock Reconciliation，避免采购/销售完整流程 |
| 零成本/未填成本 | 分开测试“不提供估值率”和“显式为0”；仅在支持时启用允许零估值选项，记录每种单据是否要求、报错和默认值，不伪造成本通过验证 |
| 无需总账影响 | 在官方允许的 perpetual inventory 设置下测完整链路；记录 SLE/估值数据与 GL 条数；不开采购/销售发票；不能凭无 GL 推断无估值 |
| 非零成本对照 | 在隔离组以不同入库估值重复移库、部分接收、出库、盘点和冲销，检查数量是否改变、是否需要额外重估或后台重算 |
| 后台与纠错 | 观察待处理重估/重过账任务、错误、取消和更正后数量/估值差异，等待相关任务结束再对账 |
| 未来启用成本 | 记录零估值历史能否追溯重算、是否需切换日快照及新成本基线；未知就标待设计，不能承诺自动迁移 |

输出三类结论之一：可接受（内部仍估值，但数量操作不需虚构成本且无不需要的 GL）；需要业务/架构评审（依赖额外配置与维护）；失败（数量业务受阻或只能修改核心/放宽规则）。内部估值仍存在时，须说明与“V1 不启用估值”设计的差距，提交评审，不自行认定等价。

## 6. 每个用例的对账与证据

每次成功/失败请求都记录：运行编号、版本/commit/镜像 digest、用户与角色/仓库范围、审批与估值配置、前置基线、脱敏请求/响应、单据及行 ID、批次映射/Bundle、前后逐桶余额、有效流水、预期/实际、截图或日志、原生/适配结论、差距和复现步骤。不得保存密码、Token、真实业务合同或生产数据。

- 按 SKU + 库位 + 领域 batch（含 null）核算：`期初数量 + 有效数量增减合计 = 当前余额`。若期初已记为流水则仅求和，不重复加期初。
- 对冲销明确 ERPNext 有效流水的计入规则，不能同时忽略原记录又重复扣除反向记录；保留原单、调整单及其关联证据。
- 移库每个阶段验证 `源 + 在途 + 目标` 守恒，`累计接收 <= 累计发出`；在途按原移库行归属，多个移库不能串收。
- 核对余额汇总、批次分配、有效流水及单据数量；不能只依赖仓库 SKU 汇总证明批次正确。
- 使用应用 API/报表取证；必要的数据库类型/事务证据仅由开发者在隔离库只读检查，不授权前端直接查库或写底表。
- 任何被拒绝的请求必须验证“无副作用”；成功用例必须核对未选批次、SKU 和位置不变。

## 7. 执行顺序与停止条件

1. **先做最早否决项**：E01/E02/E04/E05（空批次语义）、E14（估值最小链路）。先证实原生限制，再评估最小适配。需要改核心就停止对应改造并报告。
2. **再做主库存链路**：S01、E03/E06、E07–E11；E08/E09 必须覆盖真实批次与无批次。每一阶段对账。
3. **权限与完整性**：E12/E13/E15、S02–S06；E16 记录产品搜索的最小证据与差距。
4. 输出原生能力、独立 App 工作量、失败/阻塞与版本局限，并提交 A/B/C 路线评审。

原 FIT-GAP 的关键集合 E01–E08、E10–E14 仍必须通过；E09/E15 以及补充的并发、冲销、精度、原子性同样不能在库存完整性验收中省略。若界面或产品搜索需后续实现，应明确差距；库存关键规则失败时不得宣布 ERPNext 适配成功或进入完整业务开发。

本计划不裁决批次大小写/空格、同仓库跨库位移库是否强制两阶段、盘点冻结或预留。首轮盘点在该用例组无并行交易时执行，只验证按批次调整；实际盘点并发策略待确认后补测。API 字段仍以现有草案为基线，原型暴露的任何差异单独记录。
