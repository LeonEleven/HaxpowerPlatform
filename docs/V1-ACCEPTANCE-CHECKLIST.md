## 权限、对账与兼容

- [ ] A11（E12/E13，V1-04/05、V1-15、V1-20）在三个仓后新增第四仓，ALL 自动含新仓；SELECTED、空列表和 NONE 执行正确。多角色合并仅影响操作权限。匿名、停用、纯查询、单侧移库和失权后的访问按矩阵拒绝。
- [ ] A12（E13，V1-05、V1-15、V1-16A/B/C、V1-20/21）逐入口证实权限。覆盖业务 API、猜测 ID 的详情、聚合/分页总数，在途、报表、Prepared Report、打印、生成及下载导出、私有文件、标准 REST v1/v2、`frappe.client`、Desk、批量 CRUD、原生库存单据与启用的后台任务。所有员工角色以及已知高权限标准入口纳入矩阵。独立验证产品/库存读取、Excel 字段投影及技术筛选依赖、生成/状态/下载重验、撤权及旧文件拒绝。验证迁移预览、历史标识搜索、私有上传、跨仓文件、正式附件及反向代理无法绕过授权。
- [ ] A13（V1-14/15、V1-20/21）按组织、SKU、库位、域批次、在途归属对账。逐行验证原生单据/有效 SLE/已提交 Bundle，逐桶对标准批次余额，再汇总核 Bin。匹配操作日志、请求及受控业务行，验证故意加入孤立引用或意外取消时告警及停写。轻量审计无法保证原生账被最高权限破坏后独立重建完整历史，须验证一致恢复点和恢复后对账。
- [ ] A14（E14，V1-08、V1-17、V1-20）V1-17 相关实施前确认 B12 期初记账时点、最低估值、正式原生配置，继续确认 GL、补录和关账策略，并以隔离公司测试最低必填配置、无/零/非零估值与 GL 影响，核实关闭期间、回填截止、正常重估和破坏性重建治理。记录 ERPNext 内部估值行为和对数量的影响；业务页面及 API 只提供数量。
- [ ] A15（V1-20）在锁定版本和批准升级候选中使用合成历史复测。V1-20 以多年生产规模合成 SLE 验证部分数量操作的全量历史复核、共享锁持锁时间、查询与写入并发，以及 200,000 条 SLE 等容量保护，记录吞吐、延迟和超时恢复。V1-15 的 192 条真实合成 SLE 作为功能和性能基线。旧 ID 和 API DTO 兼容，既有批次映射、原单/反向关系、在途余量、盘点版本、幂等及私有附件升级前后对账相符，失败升级恢复后复查队列。

## 期初、界面、运维与上线

- [ ] A16（E11，V1-16A/B/C、V1-17）使用合成 Excel 验证 A/B/C 全程无数量变化及主数据映射幂等。批次报告区分已确认 NULL/空串、来源不明的 Excel 空值、空白、引号、去边变化及非法值，归并保留源行、原值、目标值、人员、时间、原因及归并前后数量。验证明盘/盲盘、实盘新增桶、未盘点与实盘零。冻结版本和摘要变更须重新审核及专项签核，覆盖默认双人、授权自审例外和全局开关关闭。原生逐桶入账核对相同批次文本的不同 SKU、无批次及零数量，覆盖分组重试、失败续跑及差异阻止放行。演示站与自动化测试站隔离，验证审核后的脱敏合成入账和安全重置。
- [ ] A17（V1-18/19）目标浏览器及网络完成登录、查询、出入库多行、两阶段移库与收退、盘点、审批、纠错、期初及导出。验证固定 Excel 列和复杂 JSON 属性列的员工可读性，并核对字段授权。无批次须明确选择；行错误及重试有反馈，前后端显示一致。
- [ ] A18（V1-21）批准的阿里云拓扑、安全组、HTTPS、最小权限、监控和值班流程通过。按 B11 验证一致备份计划、异地存储、加密与访问权限、告警投递和时限。使用同一恢复点在隔离环境还原 DB、配置和站点/私有文件，再验证 SLE、Bundle、Batch、Bin、操作历史、在途、盘点、幂等、权限和待运行任务，达到签定 RPO/RTO。
- [ ] A19（V1-22）业务、工程、运维签核，确认 G01–G12 关闭及相关 B 项签定。先冻结旧系统写入，备份，在批准窗口执行实盘，审核并专项签核冻结清单后入账、逐桶核对实物并执行烟测。未结跨仓运输原则上先处理，无法完成的须专项审核。正式员工数量 HTTP 写入在完成发布验收并取得明确授权后开放。保留旧系统只读和上线证据；出现差异、意外写入或权限异常时停写，按演练流程处置并重新签核。

任何拒绝或注入失败用例需验证业务状态、原生单据、有效 SLE、Bundle、Bin、幂等、操作日志和相关版本无意外变化。正常重估的元数据变化单独记录，数量事实和引用保持可核。签核在原生数量、业务策略、操作权限、恢复能力四方面均有可复查证据后完成。
