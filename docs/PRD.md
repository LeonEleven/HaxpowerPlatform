# HaxpowerPlatform 产品需求规格书（PRD）

版本 0.1.0 \| 日期 2026-11-16 \| 状态：需求基线草案

## 1. 背景

公司销售船舶配件，例如活塞环、喷油嘴、出油阀等。现有 ERP
是多年以前开发的库存系统，技术栈老旧、维护困难、操作体验一般。新项目名为
HaxpowerPlatform。旧系统截图、字段和业务行为只用于理解业务，不复用旧系统源代码。

## 2. 规模与环境

| 项目         | 当前情况                             |
|--------------|--------------------------------------|
| 主操作人员   | 约 1 名                              |
| 查询人员     | 约 10 名                             |
| 具体库存产品 | 1000 种以内                          |
| 当前仓库     | 3 个，系统不得写死数量               |
| 库位         | 每个仓库多个                         |
| 访问方式     | 互联网浏览器访问，不限于局域网       |
| 服务器       | 已有阿里云 Linux 服务器              |
| 客户端       | 部分电脑较老，员工计算机操作能力不一 |
| 开发方式     | 本地 VSCode + Codex                  |

## 3. 项目目标

1.  建立适合船舶配件行业的产品档案和动态属性。
2.  按品牌 SKU 管理库存。
3.  支持任意数量仓库及库位。
4.  支持可空批次，并按批次独立核算。
5.  支持批量入库、出库、移库、盘点和库存流水。
6.  支持可配置审批。
7.  支持角色权限和员工级仓库数据范围。
8.  提供简单、快速、适合老旧电脑的界面。
9.  为小程序、OCR/AI、采购销售及估值扩展预留接口。

## 4. 用户和角色

初始角色建议： - 管理员：系统配置、用户、角色和全部数据。 -
库存查询员：查询获授权仓库库存和流水。 -
仓库操作员：按授权仓库办理入库、出库、移库、盘点。 -
技术员：维护产品分类、属性模板、规格和 SKU。 -
审批员：审批启用时处理库存单据。

员工可拥有多个角色。角色定义“能做什么”；用户仓库数据范围定义“能访问哪些仓库”。

## 5. V1 功能范围

### 5.1 账号和权限

- 登录、登出、账号启停。
- 一个员工可有多个角色。
- 菜单/页面、查看、新增、编辑、提交、审批、导出等操作权限。
- 仓库范围支持 ALL、SELECTED、NONE。
- 服务端强制执行权限。

### 5.2 产品档案

- 产品分类可配置，不写死喷油嘴、活塞环等类别。
- 分类可配置属性模板。
- 属性支持文本、数值、单选、多选、布尔、日期等类型。
- 属性可维护 100+ 候选选项。
- 选项属性配置单选或多选。首批 23 项技术属性均选填且可搜索，模板及字段见 [首批配置](V1-16-PRODUCT-CONFIGURATION-AND-MIGRATION.md)。
- 属性可配置必填、搜索、规格匹配等行为。
- 产品规格与品牌库存 SKU 分离。
- 同一规格可关联多个品牌 SKU。
- 规格及 SKU 采用系统分配的关联编码，首次迁移全面使用新编码，旧编码保留为可授权搜索的历史标识。产品维护与参数维护独立授权。
- 支持别名、件号、刻印号等搜索标识。
- 属性选项变更不自动改写已有产品；主动编辑时才修改，并记录审计。

### 5.3 仓库与库存

- 仓库数量不限，可新增、停用。
- 每个仓库有多个库位。
- V1 不要求货架/货格层级。
- 库存按 SKU + 仓库 + 库位 + 批次管理。
- 批次为自由文本，可为空。
- 同一 SKU 下相同批次号复用同一批次记录；不同 SKU 可用相同批次文本。
- 同一 SKU 可同时存在有批次和无批次库存。
- 出库、移库、盘点必须明确选择批次或无批次库存。
- 禁止负库存。
- 库存流水不可直接修改或删除。
- 单位支持整数及小数精度配置。

### 5.4 库存业务

- 批量入库、批量出库。
- 移库发出、接收两个阶段。
- 在途库存及部分接收。
- 按批次盘点。B05-01–04（项目负责人，2026-11-25）批准盘点不冻结库存，支持单库位 LOCATION、指定 SKU 全批次和明确 BUCKET 三种范围；不设固定时限，按库存版本失效并新建快照重新实盘；允许经授权及原截止账面零证明的发现桶盘盈。审批遵循 B06，正式记账截止仍待 B12。
- 库存查询、产品库存详情和库存流水。
- Excel 期初库存导入。

### 5.5 审批

- V1 提供默认关闭的站点全局库存审批开关。系统维护人员带原因修改，开关记录版本及前后值。
- 关闭时，常规入库、出库和盘点通过校验后生效，移库提交后待发出。开启时，常规提交先待审批。
- 具有对应审批权及全部相关仓库范围的创建人可自审。
- 每次提交固化当时开关、单据版本和业务内容。审批保留提交人、审批人、实际触发人与原生执行身份，并记录时间、意见和结果。
- 待审可由创建人撤回，驳回和撤回后的重提形成新快照。生效重验失败保持待审，过期盘点另建任务。
- 纠错始终需要专项审批，正式期初入账始终需要专项签核。
- 入库、出库、移库、盘点纳入审批策略。
- 移库仍分发出和接收两阶段，接收和带原因的剩余在途退回无需重复审批。

### 5.6 查询和界面

- 支持中文、英文、编码、件号、别名、品牌和属性关键词组合搜索。
- 支持按仓库、库位、批次筛选。
- 列表服务端分页，搜索输入防抖。
- 重点操作减少点击步骤。
- 表格清晰、错误提示明确。
- 不以复杂图表作为主要操作入口。
- 支持批量录入和受权限控制的 Excel 导入导出。

## 6. V1 暂不做

- 采购订单、销售订单完整流程。
- 财务、应收应付、总账。
- 询报价、税价、折扣率。
- 库存金额、成本、利润和估值报表。
- 自动生成批次编码。
- 产品替代关系。
- 货架/货格多级管理。
- AI 自动提交库存单据。
- 微信小程序（只预留 API）。

## 7. 核心库存规则

- 库存数量不允许小于零。
- 草稿可暂存超库存数量，正式提交必须校验。
- 入库批次可空。
- 出库必须明确选择具体批次或无批次库存。
- 移库保留原批次。
- 移库发出后进入在途；接收后才进入目标库位。
- 部分接收后剩余数量继续在途。
- 正式流水不可直接修改/删除。
- 库存余额必须与有效流水一致。

## 8. 数据迁移

按 B03 和 B10 提前迁移主数据，异常批次进入预览复核。切换时冻结旧写入，以专项签核的实盘清单建立正式期初，并逐桶核对。旧系统只读保留历史流水，历史差异作为迁移证据。支持明盘和盲盘，首次切换优先盲盘。 [V1-16 需求及规划](V1-16-REQUIREMENTS.md)

## 9. 非功能需求

- 目标规模约 11 名初始用户、1000 种以内 SKU。
- 列表分页，禁止无界加载全部流水。
- 数据库对编码、SKU、仓库、库位、批次和搜索字段建立索引。
- 页面适合老旧电脑和弱网络。
- 全站 HTTPS，数据库/Redis 不直接暴露公网。
- 关键操作审计、定时备份和恢复演练。
- API 版本化，业务模型与框架尽量解耦。

## 10. 验收重点

1.  同一 SKU 同时存在 STD61、STD62 和无批次库存。
2.  出库只扣减明确选择的库存桶。
3.  移库发出进入在途，接收后进入目标库位。
4.  部分接收后剩余数量继续在途。
5.  新增第四个仓库无需改代码。
6.  ALL 自动包含未来仓库；SELECTED 不自动包含。
7.  API、报表、导出不能绕过仓库权限。
8.  库存不足不能正式提交。
9.  重复提交不重复变更库存。
10. 期初导入区分有批次和无批次。

## 11. 待确认

- 批次号大小写规则。
- 同仓库不同库位移库是否也要两阶段确认。
- B05 已批准非冻结、三种范围、版本过期及受控新增桶（2026-11-25）；审批遵循 B06，正式记账截止仍待 B12。
- Chrome/Edge 的具体兼容版本。
- 查询人员是否能查看产品技术档案全部字段。

### V1-14 纠错和审计

项目负责人于 2026-11-26 批准 B07/B08。已生效库存业务使用新增反向单纠错，支持部分、多行和累计额度，始终需要专项审批。发生同桶后续交易、重新盘点或已接收移库时，由有权限人员登记和处置人工审核。错 SKU、批次或库位完成反向后，再按既有业务审批及权限正确入账并建立追溯关系。正式历史长期保留，生产备份实施和估值仍按 B11/B12 审查。

### V1-15 查询及报表

B02/B09 获批范围见 [项目决策](DECISIONS.md#11-b02-和-b09-查询权限及功能范围)。可通过多个关键词组合查找品牌 SKU，并使用分类、品牌、精确属性、仓库、库位和批次筛选。授权库存按 SKU 汇总后可展开逐桶分布，在途单列。产品目录可独立查看业务字段。报表提供当前库存、收发明细、期间数量、在途、业务单和纠错追溯，导出具备独立授权。
