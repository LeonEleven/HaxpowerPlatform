# 权限设计

## 1. 总体原则

权限分为两套独立规则： 1. 角色权限：决定用户可以执行什么操作。 2.
仓库数据范围：决定用户可以访问哪些仓库的数据。

两者必须同时满足。仅隐藏前端按钮不构成安全控制，服务端
API、查询、报表、导出都必须执行权限检查。

## 2. 多角色

一个员工可以拥有多个角色。操作权限按角色授予集合合并（union）。例如同时有库存查询员和仓库操作员角色，可获得两者授予的操作权限。

仓库数据范围不因多个角色自动扩大，使用独立的用户级配置。

## 3. 初始角色建议

| 角色       | 产品档案       | 库存查询   | 入库 | 出库 | 移库 | 盘点 | 审批 | 用户管理 |
|------------|----------------|------------|------|------|------|------|------|----------|
| 管理员     | 全部           | 全部       | ✓    | ✓    | ✓    | ✓    | ✓    | ✓        |
| 库存查询员 | 查看（可配置） | ✓          | ✗    | ✗    | ✗    | ✗    | ✗    | ✗        |
| 仓库操作员 | 查看           | ✓          | ✓    | ✓    | ✓    | ✓    | 可选 | ✗        |
| 技术员     | 管理           | 可查看     | ✗    | ✗    | ✗    | ✗    | ✗    | ✗        |
| 审批员     | 按授权查看     | 按授权查看 | ✗    | ✗    | ✗    | ✗    | ✓    | ✗        |

此矩阵是初始建议，管理员可调整。V1 不配置价格/成本权限，因为 V1
不提供相关功能。

## 4. 用户仓库范围

每个用户配置一种模式：

### ALL

可访问所有当前仓库；未来新增仓库自动纳入。适合管理员和全局查询人员。

### SELECTED

只能访问管理员逐个授权的仓库；新仓库默认不授权。授权列表为空时拒绝访问。

### NONE

无权访问任何仓库库存数据。

当前约 10 名查询人员可配置为 ALL。未来如需限制，改为 SELECTED
并逐个勾选仓库。

## 5. 权限计算

查询：`具备对应功能权限 AND 用户仓库范围允许`。

写操作：`具备对应操作权限 AND 源/目标仓库均在授权范围内 AND 业务校验通过`。

移库： - 创建/发出阶段校验源仓库和目标仓库访问权限。 -
接收阶段校验目标仓库权限。 - V1
同一操作人员完成两阶段时，必须对源和目标仓库都有权限。 -
未来可由不同员工分别执行发出和接收。

## 6. 必须受仓库范围保护的资源

库存列表、产品库存详情、批次库存、库存流水、库存单据、在途库存、报表、Excel
导出、API 搜索和详情、与受限单据关联的附件。

不能先查出全部库存再仅在前端过滤；必须在服务端查询和权限层统一约束。

## 7. 产品档案与库存权限分开

员工可能有权查看产品名称和技术规格，但无权查看某些仓库库存数量。产品技术档案查看权限与库存数据范围分开配置。

## 8. 管理员

管理员拥有系统管理权限。管理员账号数量应受控，启用强认证并记录关键操作。管理员
API 密钥不得嵌入浏览器或小程序。

## 9. ERPNext 适配

Frappe 原生支持多角色、DocType 权限、字段权限和 User Permissions： -
https://docs.frappe.io/framework/user/en/basics/users-and-permissions -
https://docs.frappe.io/erpnext/user-permissions

自定义库存
API、报表、导出必须自行验证和补充权限检查，不能只依赖标准表单权限。
