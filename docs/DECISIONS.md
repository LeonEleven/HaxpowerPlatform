## 2. 产品模型建议

- 产品分类、产品规格、品牌库存 SKU 分层。
- 同规格不同品牌建立不同 SKU。
- 属性模板可配置。
- 属性选项可超过 100 个。
- 属性是否允许单个产品多选，由属性配置决定。
- 产品属性主动编辑时才改变，并保留审计历史。
- 产品替代关系暂不做。

产品规格与 SKU 分层是推荐的数据建模方案，需在 PRD 评审时确认。

## 3. 库存模型建议

- 库存维度：SKU + 仓库 + 库位 + Batch（nullable）。
- 无批次使用真正的 `batch_id = NULL`。
- ERPNext 适配层按 SKU 维护独立系统 Batch，对外仍为 `batch_id = NULL`；Stage 1B 验证过精确收发，Stage 1D 验证过两阶段移库。
- 正式业务更正追加新单据，业务服务不直接更新或删除库存流水。原生重估可更新技术字段，原生取消与后台边界纳入生产验收。
- 库存余额由正式流水和交易维护。
- 在途作为独立库存位置或专门余额。
- 所有数量使用精确 Decimal。

## 4. 权限建议

- 多角色操作权限合并。
- 用户级仓库范围独立配置。
- ALL 自动包含未来新增仓库。
- SELECTED 只包含明确授权仓库。
- NONE 无仓库访问。
- 所有 API、报表、导出和详情均做服务端权限检查。

## 5. 技术路线状态

- **已获项目方原则批准的 V1 首选路线**为 ERPNext v16 + 独立 HaxpowerPlatform Frappe App。员工通过 Haxpower 界面及受控业务 API 办理库存。原生库存执行由 ERPNext 提供，通过受支持接口集成，核心源码保持原样。
- Stage 1B–1F 已验证实验范围内的系统 Batch 映射、权限边界、部分接收、并发及审计。Stage 2B 使用原生有效 SLE 和轻量纠错日志验证相同范围的追溯，建议作为审计基线，生产验收仍有条件。
- Frappe-only 为 Stage 2A 已验证的备选路线。正式实施受审计方案、权限、备份恢复及库存验收约束。

## 11. B02 和 B09 查询、权限及功能范围

项目负责人于 **2026-11-27（Asia/Shanghai）** 在 V1-15 任务书第二节批准下列规则。

- B02 准许 PRODUCT_READ 员工读取完整业务技术字段，管理审计及系统内部字段由独立能力控制。现有查询岗位以 ALL 为配置基线，保留 ALL、SELECTED、NONE。缺配置仍默认拒绝。初始角色矩阵见 [权限设计](PERMISSIONS.md#3-初始角色矩阵)。
- B02 库存与业务流水按授权仓库读取，审批及管理审计独立授权。Excel 独立授权。库存默认以品牌 SKU 汇总，可展开逐仓、库位和批次。在途单列。物理和在途均为零的 SKU 默认隐藏，可主动显示，也可独立检索产品档案。
- B09 V1 采用动态技术属性，库存预留及独立包装、重量、长度数量账留到后续需求评审。桌面 Chrome/Edge 优先，手机辅助，兼容版本待确认。V1 无 IE 或扫码设备要求。支持多关键词组合查询同一品牌 SKU，例如“活塞环 320 RIKEN”。

同一 SKU 的 AND 组合、NFKC、精确类型筛选及现有关键词上限是 V1-15 架构评审的技术方案，详见 [产品模型](PRODUCT-MODEL.md#14-v1-15-员工搜索)。实际员工分配、仓库编码、维护职责和具体浏览器版本仍待确认。
