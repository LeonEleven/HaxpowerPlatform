## 2. 产品模型建议

- 产品分类、产品规格、品牌库存 SKU 分层。
- 同规格不同品牌建立不同 SKU。
- 属性模板可配置。
- 属性选项可超过 100 个。
- 属性是否允许单个产品多选，由属性配置决定。
- 产品属性主动编辑时才改变，并保留审计历史。
- 产品替代关系暂不做。

产品规格与 SKU 分层是推荐的数据建模方案，需在 PRD 评审时确认。

## 3. 库存模型建议

- 库存维度：SKU + 仓库 + 库位 + Batch（nullable）。
- 无批次使用真正的 `batch_id = NULL`。
- ERPNext 若无法原生表示空批次，可评估适配层特殊 Batch；尚未验证。
- 库存流水不可直接更新/删除。
- 库存余额由正式流水和交易维护。
- 在途作为独立库存位置或专门余额。
- 所有数量使用精确 Decimal。

## 4. 权限建议

- 多角色操作权限合并。
- 用户级仓库范围独立配置。
- ALL 自动包含未来新增仓库。
- SELECTED 只包含明确授权仓库。
- NONE 无仓库访问。
- 所有 API、报表、导出和详情均做服务端权限检查。

## 5. 技术路线状态

尚未最终决定： - A：ERPNext + 自定义 Frappe App。 - B：Frappe
Framework + 自研库存引擎。 - C：独立前后端技术栈。

当前建议优先验证
A，但关键批次空值、库存估值、权限和部分接收测试未通过前不得最终决定。

## 6. 待确认事项

1.  哪些具体属性允许一个产品选择多个值。
2.  批次号大小写是否敏感、首尾空格如何处理。
3.  同仓库不同库位之间移库是否也必须两阶段确认。
4.  盘点期间是否冻结库存。
5.  是否需要库存预留/锁定。
6.  查询人员是否可查看产品技术档案全部字段。
7.  是否需要记录数量以外的包装、重量或长度辅助信息。
8.  最终数据库、前端和后端技术栈。
9.  ERPNext 特殊无批次方案能否完整验收。
10. ERPNext 内部估值行为是否与 V1 只管数量目标冲突。

## 7. 决策变更

业务规则变更时更新本文件和对应 PRD/模型/流程/API 文档。涉及库存模型或
API 的破坏性变更，必须提供数据迁移方案。
