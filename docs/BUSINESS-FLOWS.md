# 库存业务流程

## 1. 通用单据状态

- Draft：草稿
- Pending Approval：待审批
- Approved：已审批
- Rejected：已驳回
- Posted：已生效（入库/出库/盘点调整）
- In Transit：在途（移库）
- Partially Received：部分接收
- Completed：完成
- Cancelled：取消

正式库存变更必须关联单据和操作人。

## 2. 全局审批开关

V1 设置 `inventory_approval_enabled`。

### 关闭

- 入库/出库/盘点：提交后校验并直接生效。
- 移库：提交后可进入发出确认，不跳过发出和接收两阶段。

### 开启

- 入库/出库/移库/盘点：提交后进入待审批。
- 审批通过后才可正式生效或发出。
- 当前允许创建人审批自己的单据。
- 审批保留操作者、时间、意见和结果。

未来可扩展按单据类型配置和多级审批，V1 不实现复杂工作流。

## 3. 入库

1.  新建入库单。
2.  选择目标仓库和库位。
3.  批量添加 SKU。
4.  填写数量和单位。
5.  草稿可暂未选择批次。正式提交前填写实批次或明确选择“无批次”。首尾空白变化须确认，候选值与原文冲突时进入复核。
6.  保存草稿。
7.  提交；审批开启则待审批，否则校验并生效。
8.  生效时写入库存流水并更新余额。
9.  记录操作人、时间和单据关联。

重复提交必须幂等，不能重复增加库存。

## 4. 出库

1.  新建出库单。
2.  选择出库仓库/库位。
3.  批量添加 SKU。
4.  系统展示该 SKU 在所选库位的批次库存。
5.  每行明确选择具体批次或“无批次”。
6.  输入数量。
7.  保存草稿。
8.  提交时服务端校验批次库存和总库存。
9.  审批开启则审批通过后扣减；关闭则提交后扣减。
10. 写入流水并更新余额。

不能因为 STD61 不足就自动从 STD62 或无批次库存扣减。

## 5. 移库

移库必须保留批次，并分发出、接收两个阶段。

### 发出阶段

1.  创建移库单。
2.  选择源仓库/库位、目标仓库/库位。
3.  添加 SKU、批次/无批次和数量。
4.  提交审批（若开启）。
5.  审批通过后发出确认。
6.  发出确认后源位置减少、在途位置增加。
7.  状态变为 In Transit。

V1-10 的隔离候选在草稿与发出时均校验操作权限和源、目标仓库范围。发出确认将原货从源库位转入同公司系统在途，并按原发出行保留归属。该行的目标库位要在未来接收时才增加。出库和普通入库服务拒绝使用系统在途位置。

### 接收阶段

1.  目标仓库确认收到。
2.  输入实际接收数量。
3.  接收数量不得超过剩余在途数量。
4.  在途减少，目标库位增加。
5.  全部收到则 Completed；部分收到则 Partially Received，剩余继续在途。

示例：发出 30，第一次收到 29：目标库位 +29，在途剩余
1，后续继续接收或按异常流程处理。未接收数量不能直接删除。

V1
是否允许同仓库不同库位之间移库，需确认；模型应允许源、目标为不同库位。

## 6. 盘点

1.  创建盘点任务，选择仓库/库位。
2.  生成账面 SKU、批次（含无批次）数量。
3.  录入实盘数量。
4.  计算差异。
5.  提交审批（若开启）。
6.  审批通过或直接确认后生成调整流水。
7.  保存盘点前后数量、差异、操作人和时间。

盘点期间是否冻结库存尚待确认；若不冻结，必须定义盘点截止时间和期间流水处理规则。

## 7. 库存查询

按产品分类、规格、SKU、品牌、仓库、库位、批次/无批次、件号、别名和属性关键词查询。产品列表可先显示汇总数量，点击详情显示各仓库、库位和批次分布。所有查询按用户仓库范围过滤。

## 8. 冲销与纠错

- 正式库存单据不能直接删除。
- 发现错误时创建冲销/退回/调整单据。
- 冲销引用原单据和原流水。
- 已发生后续交易时不能简单回滚余额，需按业务顺序处理并保留审计链。

## 9. 期初库存导入

1.  建立 SKU、仓库、库位和批次档案。
2.  导入每个 SKU、库位、批次的期初数量。
3.  批次不明的数量导入无批次库存。
4.  记录统一期初日期/时间和来源文件。
5.  核对各仓库、SKU 汇总及实物结果。
6.  导入完成后锁定导入批次；修正使用正式调整单据。
