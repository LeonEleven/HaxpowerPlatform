## 权限、对账与兼容

- [ ] A11（E12/E13，V1-04/05、V1-15、V1-20）在三个仓后新增第四仓，ALL 自动含新仓；SELECTED、空列表和 NONE 执行正确。多角色合并仅影响操作权限。匿名、停用、纯查询、单侧移库和失权后的访问按矩阵拒绝。
- [ ] A12（E13，V1-05、V1-15、V1-20/21）逐入口证实权限。覆盖业务 API、猜测 ID 的详情、聚合/分页总数，在途、报表、Prepared Report、打印、生成及下载导出、私有文件、标准 REST v1/v2、`frappe.client`、Desk、批量 CRUD、原生库存单据与启用的后台任务。所有员工角色以及已知高权限标准入口纳入矩阵。
- [ ] A13（V1-14/15、V1-20/21）按组织、SKU、库位、域批次、在途归属对账。逐行验证原生单据/有效 SLE/已提交 Bundle，逐桶对标准批次余额，再汇总核 Bin。匹配操作日志、请求及受控业务行，验证故意加入孤立引用或意外取消时告警及停写。
- [ ] A14（E14，V1-08、V1-20）以隔离公司测试最低必填配置、无/零/非零估值与 GL 影响，核实关闭期间、回填截止、正常重估和破坏性重建治理。记录 ERPNext 内部估值行为和对数量的影响；业务页面及 API 只提供数量。
- [ ] A15（V1-20）在锁定版本和批准升级候选中使用合成历史复测。旧 ID 和 API DTO 兼容，既有批次映射、原单/反向关系、在途余量、盘点版本、幂等及私有附件升级前后对账相符，失败升级恢复后复查队列。

## 期初、界面、运维与上线

- [ ] A16（E11，V1-16/17）先跑合成 Excel。报告区分源 NULL、空串、全空白、空引号、去边变化和非法值；候选归并有审核人、决定、时间和文件来源。清单不可悄变，分组重放续跑无重复；失败或差异时不放行。逐桶核对包含相同显示批次的不同 SKU 和无批次。
- [ ] A17（V1-18/19）目标浏览器及网络完成登录、查询、出入库多行、两阶段移库与收退、盘点、审批、纠错、期初及导出。无批次须明确选择；行错误及重试有反馈，前后端显示一致。
- [ ] A18（V1-21）批准的阿里云拓扑、安全组、HTTPS、最小权限、监控和值班流程通过。验证备份计划、异地备份、告警投递和时限。使用同一恢复点在隔离环境还原 DB、配置和站点/私有文件，再验证 SLE、Bundle、Batch、Bin、操作历史、在途、盘点、幂等、权限和待运行任务，达到签定 RPO/RTO。
- [ ] A19（V1-22）业务、工程、运维签核，确认 G01–G12 关闭及相关 B 项签定。先冻结旧系统写入，备份并审核最新快照，再在已批准窗口导入、逐桶与实物对账、执行烟测，经授权开放。保留旧系统只读和上线证据；出现差异、意外写入或权限异常时停写，按演练流程处置并重新签核。

任何拒绝或注入失败用例需验证业务状态、原生单据、有效 SLE、Bundle、Bin、幂等、操作日志和相关版本无意外变化。正常重估的元数据变化单独记录，数量事实和引用保持可核。签核在原生数量、业务策略、操作权限、恢复能力四方面均有可复查证据后完成。
