## 工程、主数据和权限

### V1-01 正式 App 骨架及开发基线

- **目标** 从干净检出建立可重复的工程入口。**依赖** Stage 3A 审查完成。**范围** `apps/haxpower_v1/` 包元数据、Hooks、测试与迁移夹具，`dev/v1/` 环境模板、版本锁和操作说明，`.github/workflows/`，同步技术文档与交接进度。
- **必须实现** 安装独立 Bench 与正式站点的开发入口、目标校验、锁定上游版本、最小 App 安装与测试命令、CI 作业内独立资源、可复跑迁移和失败诊断。以无业务的 DocType 或补丁夹具验证迁移，PR 仅包含工程基线。
- **自动化测试** 空站装 ERPNext 和正式 App、同一站点 migrate 两次、有旧合成记录的夹具升级并保留记录、拒绝实验配置标识、核对两套包路径和核心来源；CI 输出脱敏版本和迁移结果。
- **验收标准** 第二个干净工作区能按说明复现；CI 通过且无脏上游源码，迁移复跑后的结构/夹具一致；CI 只回收本次运行的资源。**风险** 路由或默认站点误指、Python 包冲突、共享卷、DDL 部分完成、CI 凭据泄漏。**待确认** 无业务问题；正式生产拓扑在 B11 评审。

### V1-02 分类、属性与规格

- **目标** 完成产品档案的规格层。**依赖** V1-01。**范围** `catalog` 服务、分类/模板/选项/规格 DocType、属性编辑审计、领域 DTO。

- **自动化测试** 必填与类型、单选数量上限、多选去重、停用选项后的既有规格读取、非维护用户写入拒绝、冲突规格保留；权限集成待 V1-05 复测。
- **验收标准** 可用合成数据完成分类到规格的维护与审计；旧属性值不会随选项变化改写。**风险** 字段类型变更使既有值不可读，属性维护权限过宽。**待确认** B01 具体多选字段及首批模板。

### V1-03 品牌 SKU 与原生 Item 映射

- **目标** 将品牌库存 SKU 接入原生主数据。**依赖** V1-02。**范围** `catalog/sku`、别名与标识 DocType、`adapters/erpnext/item`。

- **自动化测试** 同规格不同品牌、别名搜索、重复编码/映射并发、映射失败回滚、配置超出原生能力时报错。

### V1-04 仓库与库位映射

### V1-05 仓库授权和原生入口守卫

- **目标** 建立后续各模块复用的权限边界。**依赖** V1-03、V1-04。**范围** `access`、`hooks.py`、角色/仓库范围、原生 DocType 与 API 守卫、权限矩阵。

- **自动化测试** 真实 HTTP 验证匿名/停用/查询/操作/审批、多角色、空 SELECTED、W4、两侧授权、原生 REST v1/v2、`frappe.client`、Desk 和批量入口；验证失权后的详情访问。
- **验收标准** 员工通过受控 API，合成受管原生记录的直接读写按矩阵拒绝，守卫覆盖可用入口并记录未启用路径。**风险** 原生角色叠加、服务身份超权、后台与管理员旁路。**待确认** B02 权限矩阵和档案字段，B04 接收角色；运维账号见 B11。

- **自动化测试** Unicode 首尾空白、大小写与全半角、空引号、含内容引号、控制字符、前缀、跨 SKU 同文本、唯一性并发、错误及详情响应脱敏。
- **验收标准** 同 SKU 的实批次和无批次相互独立；原生内部标识仅用于适配层，可由业务证据追踪而无对外泄漏。**风险** 数据库排序规则合并批次，历史值静默归并和系统桶污染。**待确认** B03 正式字符、等价和清洗政策。

## 正式库存内核

### V1-07 多行事务、幂等与轻量日志

- **目标** 提供各库存命令共用的原子执行契约。**依赖** V1-05、V1-06。**范围** `stock_documents` 基础 DocType、`inventory/execution`、`operations`、请求/日志/关联表、版本更新接口。
- **必须实现** 稳定多行身份、Decimal 校验、同桶需求合计、固定锁顺序、当前读、事务边界、幂等唯一索引与规范负载摘要，日志头/关联行及生效唯一性。先用内部测试入口验证事务，不开放员工库存命令。
- **自动化测试** 连接真并发下同键同负载/异负载、等待锁前已有读取、相反行序、空桶、当前读、故障回滚及提交回包丢失；校验日志头行与重复命令状态。
- **验收标准** 仅一次成功状态和可追踪原生关联；拒绝及故障后新连接查无半提交。**风险** 原生内部提前提交、隔离级别快照过期、日志写失败、幂等过期重放。**待确认** B08 留存和重试窗口，B01 精度。

### V1-08 多行入库

- **目标** 实现按行精确入库。**依赖** V1-07。**范围** 入库草稿、提交命令、API DTO、原生 Material Receipt 适配。
- **必须实现** 多行不同 SKU/库位/批次与无批次的校验、草稿及正式提交、原生单据行链接、数量流程最低估值配置的实测。
- **自动化测试** 混合有/无批次、同桶多行、异单位精度、重复和无权限、第 N 行失败整单回滚、原生提交成功后日志失败回滚。
- **验收标准** 多行结果逐桶和逐行一致，受保护配置下可重复提交原结果；估值与 GL 结果有证据。**风险** 默认批次、未经验证的估值设置、拆单中途落账。**待确认** B01、B03、B12。

### V1-09 多行出库

- **目标** 完成精确扣减与并发防超卖。**依赖** V1-08。**范围** 出库草稿/提交 API、`inventory/availability`、原生 Material Issue 适配。
- **必须实现** 按批次桶证明库存充足、合计重复桶需求、并发提交时复验，禁止跨桶补足或自动分配。
- **自动化测试** 正常有/无批次扣减、超扣、缺选择、不同键并发，PC 小数拒绝，小数单位精确往返、第二行未授权/不足后的完整回滚。
- **验收标准** 并发争用仅有可满足的单据生效，非选中桶无变化。**风险** 两请求读同一旧余额、暂存草稿越权和原生自动分配。**待确认** B09 预留需求，V1 基线不实现预留。

### V1-10 移库发出

- **目标** 从源库位发到系统在途。**依赖** V1-09。**范围** 移库草稿/发出、在途归属、原生 Material Transfer 适配。
- **必须实现** 源目标双授权、目标及行身份固化、逐行绑定原生发出单和在途引用，必要时按目标拆原生单，维持整个动作原子性。
- **自动化测试** 多行有/无批次、两个方向的单侧越权、两笔移库同 SKU/桶不串归属、重复发出、同仓规则分支、在途普通出库拒绝。
- **验收标准** 发出后源减少、在途等量增加、目标不变，两侧授权和归属可查。**风险** 系统在途混用、目标被修改、逻辑仓与物理叶仓错配。**待确认** B04 同仓不同库位。

### V1-11 部分接收与剩余退回

- **目标** 接续同一发出行完成移库。在途退回作为独立原生反向动作。**依赖** V1-10。**范围** 接收/退回命令、原生 End Transit、移库累计与关闭状态。
- **必须实现** 逐行校验剩余、目标、原批次及双侧授权；支持部分、多次接收和仅退剩余在途；关闭后拒绝继续接收或退回。
- **自动化测试** 发 10 接 6 退 4，混合行与批次、多次收齐、超收/跨行、并发接收、接收与退回争用、重放及提交失败。
- **验收标准** 每行已发等于已收加已退加在途，源/在途/目标守恒，退回保持累计实收真实。**风险** 不同移库消耗同一在途桶、累计混用，已接收量错误退回。**待确认** B04 岗位，B07 退回审批及下游补偿。

### V1-12 盘点任务、版本及调整

- **目标** 按截止快照安全生效盘点差异。**依赖** V1-11。**范围** `stock_count`、桶/范围版本、原生 Stock Reconciliation 或经评审调整适配。
- **必须实现** 生成任务快照和范围/桶版本，按锁序重验，追加差异并保存原生关系；无差异可结束，旧任务拒绝，回填引入新版本代次。所有已完成数量命令须推进受影响版本。
- **自动化测试** 有/无批次、实盘零、往返同净量、新桶、并发更新/审批前陈旧、正常重估数量不变、旧任务迁移与重放。
- **验收标准** 旧版本不可入账，正确版本的多行调整可对账，原生记录与任务一同提交。**风险** 漏推进导致旧任务覆盖余额，回填把不可信旧任务升级为有效。**业务批准** B05-01–04 于 2026-11-25 批准非冻结、三种范围、无固定时限的版本过期重盘及授权新增桶。**待确认** B12 记账截止；A06 仍待 V1-13 和 V1-20。

### V1-13 审批开关与状态流转

- **目标** 将审批和库存生效纳入同一流程。**依赖** V1-08、V1-09、V1-11、V1-12。**范围** `approval`、库存单据状态/审批历史、服务端命令和流程文档。
- **必须实现** 全局开关、提交/批准/驳回、具审批权者自审、人员/时间/意见/结果留存。入库、出库、盘点审批生效时重验库存及版本；移库审批后仍须发出和接收；失败处理保留可解释状态。
- **自动化测试** 开/关两路、并发审批与重放、单侧权限、自审、驳回、审批期间库存或盘点版本变化、开关处理中变化、批准写库存时故障。
- **验收标准** 待审批无数量影响，决策有历史，开关关闭也不跳过移库两段。**风险** 开关变化绕过审批、审批回滚后留下假成功状态、借原生 Workflow 绕开。**待确认** B06 待审单切换、附属动作及撤回策略。

### V1-14 反向业务纠错与日志追溯

- **目标** 保留原始数量事实并支持授权追溯。**依赖** V1-11、V1-12、V1-13。**范围** `corrections`、`operations` 查询、原单与原行关联、纠错入口文档。
