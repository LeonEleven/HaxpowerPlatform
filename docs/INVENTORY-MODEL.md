# 库存模型设计

## 1. 核心原则

库存按以下维度管理：

**Stock Item（SKU） + Warehouse + Location + Batch（可空） + Quantity**

批次是库存维度，不是产品档案中的单一字段。

## 2. 批次规则（已确认）

- 批次号为自由文本，不要求固定格式。
- 入库允许无批次库存。草稿可暂未选择批次，正式提交须指定实批次或明确无批次。
- 同一 SKU 下相同批次号复用同一 Batch 记录。
- 不同 SKU 可以使用相同批次文本。
- 当前不考虑同一 SKU 的同一批次号重复使用代表不同实物批次。
- 有库存流水的批次不可删除。
- 同一 SKU 可以同时存在有批次和无批次库存。
- 领域模型中 `batch_id = NULL` 表示无批次，不创建普通假批次。
- ERPNext 若需要特殊 Batch 映射，只能存在于适配层，不能污染领域模型。

批次文本的等价规则、长度、历史例外和归并签核仍由 B03 确认。V1-06 在合成站点验证版本化候选规则。

## 3. 有批次、无批次、未选择批次

示例：

| SKU  | 仓库   | 库位     | Batch          | 数量 |
|------|--------|----------|----------------|-----:|
| 6003 | 上海办 | 正式库区 | STD61          |   12 |
| 6003 | 上海办 | 正式库区 | STD62          |   20 |
| 6003 | 上海办 | 正式库区 | NULL（无批次） |   15 |
| 6003 | 上海办 | 瑕疵库区 | NULL（无批次） |   12 |

- 实批次使用 `{"mode":"BATCH","batchNo":"STD61"}`。批次身份按 SKU 隔离，显示保留经确认的原文。
- 明确无批次使用 `{"mode":"NO_BATCH"}`。业务响应中的 `batch` 为 `null`。
- 缺少选择或模式表示未选择。提交须提供有效选择，空值、空白和疑似空引号会进入校验错误。

V1-06 在 `HP V1 Batch Mapping` 保存稳定映射 ID、SKU、种类、原文、规范键、策略版本、状态、创建身份和创建时间。每个 SKU 有自己的无批次系统桶。不同 SKU 可独立使用相同批次文本。ERPNext Batch 标识只在受控适配和管理员诊断中解析，库存模型继续以可空领域批次维度表达无批次。

[API 批次契约](API-CONTRACTS.md#4-批次字段约定) · [候选规则和原生 Batch](ERPNEXT-V1-ADAPTATION-BOUNDARIES.md#批次输入规范)

## 4. 仓库与库位

- 领域仓库可动态新增，每仓可建多个库位。V1 无需货架或货格层级。仓库和库位各有稳定 ID，库位编码在所属仓库内唯一。
- 每个域库位独占一个 ERPNext 原生叶仓。领域仓库记录公司和一个显式选择的同公司顶层 ERPNext 分组仓。多个领域仓库可引用同一个原生分组仓，各自的 ERPNext 叶仓直接挂在该分组下。所有库存维度以领域库位 ID 表示。
- V1-04 支持维护显示名称和描述。停用先检查已知库存和引用，待 V1 库存流程能够完整验证未结单据并协调并发库存写入后再开放。保留已建仓库、库位及原生映射身份。
- 普通库位选择要求仓库、库位及原生映射有效。V1-05 在领域仓库 ID 上接入员工操作权限和数据范围。仓库及库位正式编码、维护职责和授权矩阵仍属 B02。

## 5. StockBalances 当前库存余额

逻辑唯一键：

`stock_item_id + warehouse_location_id + batch_id`

字段建议： - `id` - `stock_item_id` - `warehouse_location_id` -
`batch_id`（nullable） - `quantity_on_hand`（Decimal） - `updated_at` -
`row_version`（并发控制，可选）

同一维度只能有一条余额。数据库必须处理 NULL
唯一性：有批次记录和无批次记录分别建立唯一约束/索引。

## 6. StockLedger 库存流水

库存流水是库存变动审计事实，正式写入后不可直接修改或删除。

字段建议： - `id`, `transaction_id` - `document_type`, `document_id`,
`document_line_id` - `stock_item_id`, `warehouse_location_id` -
`batch_id`（nullable） - `quantity_delta` - `transaction_type` -
`operator_id` - `occurred_at`, `created_at` - `remark` -
`reversal_of_ledger_id`（可空）

移库可形成多条流水：源库位减少、在途增加、在途减少、目标库位增加。余额更新和流水写入必须同一事务完成。

## 7. 在途库存

移库发出后，货物离开源仓库但未被目标仓库接收，应计入在途库存。

V1-04 以独立的系统在途领域仓库及库位预留该维度，并创建同公司的 ERPNext `warehouse_type = Transit` 叶仓。在途位置继承系统仓库类型，从普通仓库、库位和原生领料选择中排除。系统位置由站点运营人员通过内部服务配置。发出、接收、部分接收、退回和余额核对由 V1-10/V1-11 接入。

可以使用受系统保护的 Transit Warehouse/Location 或专门在途余额模型： -
纳入公司库存总量。 - 不纳入普通仓库可用库存。 -
普通员工不能将其当作普通仓库直接出库。 - 保留
SKU、批次、数量和原移库单关联。

部分接收时，按实收数量转入目标库位，剩余继续在途。

## 8. 禁止负库存

- 禁止负库存。
- 草稿可暂存超过库存的数量。
- 正式提交时服务端重新校验。
- 并发扣减必须安全。
- 批次库存不足不能自动从其他批次补足。
- 无批次库存不足不能自动从有批次库存扣减。

## 9. 单位与精度

- 产品数量通常是整数，其他单位可能有小数。
- 使用 Decimal/Numeric，不使用 float/double 存储库存数量。
- 每个 SKU 绑定库存单位及精度。
- PC=0、KG=3、M=3 仅为示例，实际精度可配置。
- 不允许超过单位精度的数量提交。

## 10. 盘点

按
SKU、库位、批次（含无批次）分别记录账面数量、实盘数量、差异、盘点人、时间和备注。差异通过正式调整流水生效。

盘点期间是否冻结库存尚待确认；若不冻结，必须定义盘点截止时间及盘点期间流水处理规则。

## 11. 库存估值扩展

V1 不启用金额、成本和利润。未来可增加独立的
InventoryValuationLayer、InventoryCostEntry、StockValuationAdjustment。数量流水与估值流水分离。

采用 ERPNext
时必须验证其内置估值行为，即使业务界面不展示金额，底层也可能仍维护估值数据。
