# 开发与验证计划

## 阶段 0：需求基线与技术验证（当前）

目标：核心业务代码开发前确认模型、库存规则和技术路线。

任务： - 业务方确认 DECISIONS 中已确认项。 -
评审产品、库存、权限、流程和 API 设计。 - 准备 ERPNext/Frappe 本地
Docker 开发环境。 - 创建最小 `haxpower_platform` 自定义 App。 - 建立
ERPNext 原型数据。 - 执行 ERPNext-FIT-GAP 中 E01-E16。 -
记录测试版本、截图、日志、配置和结论。

退出条件： - 关键库存测试通过。 - 不需要修改 ERPNext 核心源码。 -
库存估值影响可接受。 - 权限测试通过。 - 明确选择 A/B/C 技术路线。

## 阶段 1：系统基础

- 项目仓库、开发/测试/生产环境。
- 登录、员工、角色。
- ALL/SELECTED/NONE 仓库范围。
- 操作审计。
- 系统配置与审批开关。
- API 认证和版本控制。

验收：多角色权限正确；仓库范围不能被 API/报表/导出绕过；新增仓库对 ALL
自动可见、对 SELECTED 默认不可见。

## 阶段 2：产品档案

- 产品分类、属性定义和选项。
- 分类属性模板。
- 产品规格。
- 多品牌 SKU。
- 别名、件号和产品搜索。
- 属性变更审计。

验收：不同分类可配置独立属性；一个属性支持 100+
选项；同规格不同品牌可有不同
SKU；新增选项不改变已有产品；多条件搜索有效。

## 阶段 3：仓库与库存基础

- 仓库、库位。
- 批次档案。
- 有批次/无批次库存桶。
- 库存余额、库存流水。
- 负库存校验。
- 单位和数量精度。
- 期初库存导入。

验收：批次不混用；无批次独立存在；余额与流水一致；并发出库不超卖；重复请求不重复记账。

## 阶段 4：库存业务

- 批量入库、批量出库。
- 移库发出、接收和部分接收。
- 盘点。
- 冲销/调整。

验收：入库批次可空；出库明确批次；移库保留批次；在途数量正确；盘点按批次调整。

## 阶段 5：审批与操作体验

- 全局审批开关。
- 创建人自审批。
- 审批记录。
- 库存工作台、产品详情和库存流水。
- 批量录入体验优化。
- 老旧电脑和弱网络测试。

## 阶段 6：试运行与上线

- 确定切换日期。
- 整理期初库存。
- Excel 模板导入。
- 实物核对。
- 备份恢复演练。
- 权限检查。
- 员工培训。
- 旧系统只读保留。
- 正式上线。

## 阶段 7：未来扩展（非 V1）

微信小程序、条码/二维码、OCR 合同识别、AI
产品匹配和草稿生成、采购/销售、库存估值、产品替代关系、多级审批。

## Codex 任务拆分

每个任务必须列出：相关文档、单一功能、输入输出、状态、权限、正常/异常测试、不允许修改的模块和测试报告。不要一次性让
Codex 生成整个系统。
