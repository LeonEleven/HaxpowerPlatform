# 库存业务流程

## 1. 通用单据状态

- Draft：草稿
- Pending Approval：待审批
- Approved：移库已批准、等待发出
- Ready to Dispatch：移库提交时获审批豁免、等待发出
- Rejected：已驳回
- Posted：已生效（入库/出库/盘点调整）
- In Transit：在途（移库）
- Partially Received：部分接收，仍有在途
- Closed with Return：含退回且在途已清零
- Completed：完成
- Cancelled：取消

正式库存变更必须关联单据和操作人。

## 2. 全局审批开关

V1 的站点级 `inventory_approval_enabled` 默认关闭。

### 关闭

- 入库/出库/盘点：提交后校验并直接生效。
- 移库：提交后可进入发出确认，不跳过发出和接收两阶段。

### 开启

- 入库/出库/移库/盘点：提交后进入待审批。
- 审批通过后才可正式生效或发出。
- 拥有审批权限及全部仓库范围的创建人可自审。
- 审批保留操作者、时间、意见和结果。

每次提交固化配置版本、当前业务版本及快照。新配置从下一次提交起适用，既有待审单继续待审。
驳回须说明原因。创建人撤回后恢复草稿，驳回后也可修订，两种情形重新提交均生成新快照。
已批准移库在发出前可由具备双侧范围的审批员带原因撤销，恢复草稿。发出后沿在途流程处理。
入库、出库、盘点批准时重验权限和数量条件。失败保留待审和脱敏原因，过期盘点撤回后另建任务并重新确认实盘。
接收和余量退回沿用独立动作，余量退回须填写原因。已生效库存纠错与正式期初分别需要专项审批和签核。

## 3. 入库

1.  新建入库单。
2.  选择目标仓库和库位。
3.  批量添加 SKU。
4.  填写数量和单位。
5.  草稿可暂未选择批次。正式提交前填写实批次或明确选择“无批次”。首尾空白变化须确认，候选值与原文冲突时进入复核。
6.  保存草稿。
7.  提交；审批开启则待审批，否则校验并生效。
8.  生效时写入库存流水并更新余额。
9.  记录操作人、时间和单据关联。

重复提交必须幂等，不能重复增加库存。

## 4. 出库

1.  新建出库单。
2.  选择出库仓库/库位。
3.  批量添加 SKU。
4.  系统展示该 SKU 在所选库位的批次库存。
5.  每行明确选择具体批次或“无批次”。
6.  输入数量。
7.  保存草稿。
8.  提交时服务端校验批次库存和总库存。
9.  审批开启则审批通过后扣减；关闭则提交后扣减。
10. 写入流水并更新余额。

不能因为 STD61 不足就自动从 STD62 或无批次库存扣减。

## 5. 移库

移库必须保留批次，并分发出、接收两个阶段。

### 发出阶段

1.  创建移库单。
2.  选择源仓库/库位、目标仓库/库位。
3.  添加 SKU、批次/无批次和数量。
4.  提交审批（若开启）。
5.  审批通过后发出确认。
6.  发出确认后源位置减少、在途位置增加。
7.  状态变为 In Transit。

V1-10 的隔离候选在草稿与发出时均校验操作权限和源、目标仓库范围。发出确认将原货从源库位转入同公司系统在途，并按原发出行保留归属。该行的目标库位在接收时才增加。出库和普通入库服务拒绝使用系统在途位置。

### 接收阶段

1.  目标仓库确认收到。
2.  输入实际接收数量。
3.  接收数量不得超过剩余在途数量。
4.  在途减少，目标库位增加。
5.  全部收到则 Completed；部分收到则 Partially Received，剩余继续在途。

示例：发出 30，第一次收到 29：目标库位 +29，在途剩余
1，后续继续接收或按异常流程处理。未接收数量不能直接删除。

### 剩余在途退回

操作员选择原发出行、填写本次退回量和原因。可分多次把尚在途的货退回原源库位，
且每次保留原 SKU、库存单位和批次。发 10、收 6、退 4 后，实收 6、已退 4、在途 0，
状态为 Closed with Return。全量退回也使用该状态，保留发出和每笔退回的历史。
已有退回但仍有在途时，已有实收使用 Partially Received，实收为零使用 In Transit。
每行在途均为零时才关闭，全部实收使用 Completed。关闭后仍可读取及按当前授权重放历史请求。

双侧授权及接收、退回审批豁免按 B06 执行。B04 接收岗位及 B07 已接收或完成移库的补偿继续待确认。

V1
是否允许同仓库不同库位之间移库，需确认；模型应允许源、目标为不同库位。

## 6. 盘点

1.  创建盘点任务，选择仓库/库位。
2.  生成账面 SKU、批次（含无批次）数量。
3.  录入实盘数量。
4.  计算差异。
5.  提交审批（若开启）。
6.  审批通过或直接确认后生成调整流水。
7.  保存盘点前后数量、差异、操作人和时间。

B05 于 2026-11-25 经项目负责人批准：盘点不冻结库存，支持 LOCATION / SKU / BUCKET；以库存版本判定过期，不设固定时限。旧任务保留并另建快照、重新确认实盘。允许授权发现原账面零的新桶。见 [正式决策及来源](DECISIONS.md#8-b05-正式盘点规则2026-11-25)。审批执行按 B06，记账截止仍待 B12。

## 7. 库存查询

按产品分类、规格、SKU、品牌、仓库、库位、批次/无批次、件号、别名和属性关键词查询。产品列表可先显示汇总数量，点击详情显示各仓库、库位和批次分布。所有查询按用户仓库范围过滤。

## 8. 冲销与纠错

- 正式库存单据不能直接删除。
- 发现错误时创建冲销/退回/调整单据。
- 冲销引用原单据和原流水。
- B07/B08 已由项目负责人于 2026-11-26 批准。原行可部分、多行及多次纠错，额度按原生实际生效净额扣除历次已生效纠错。始终专项审批。
- 同桶后续交易或已完成盘点进入人工审核，保持数量不变。已接收移库走人工审核，剩余在途继续走带原因的可授权返源。
- 错 SKU、批次和库位先反向，之后通过正常业务权限和审批办理正确入账，保留两步关联。

## 9. 期初库存导入

1. 提前经审核迁移主数据，确认 SKU、仓库及库位映射。历史批次异常按 B03 审核，未知批次不得自动归入无批次。
2. 切换时冻结旧系统写入，执行实物盘点，首次优先盲盘。允许新增发现库存，未盘点和实盘零分别记录。对无法结清的跨仓在途进行专项审核。
3. 审核并冻结清单及完整性摘要。专项签核默认准备人与签核人分开，明确授权的自审例外记录授权及原因。变更须生成新版本并重新审核及签核。
4. 按 B12 审定的记账设置受控入账，零库存不产生期初流水。逐桶核对实盘与原生数量，缺组或差异阻止放行，错账使用正式调整单据。
5. 旧系统只读保留，历史库存流水留在旧系统。
