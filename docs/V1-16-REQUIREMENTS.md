## 开发规划提案

本次工作属于业务决策持久化、架构文档同步和计划更新。ChatGPT 建议将 V1-16 拆为以下任务，PR 经架构评审并由项目负责人手动合并后作为后续规划基线。每个工程任务分别使用任务书、实施授权、独立 Codex 会话、任务分支及 Draft PR。

| 任务 | 拟议交付 | 库存数量边界 |
| --- | --- | --- |
| V1-16A | 正式主数据规则、编码、历史标识、权限拆分、首批配置能力与批次策略版本治理 | 保持既有数量，验证正式 App 数据升级兼容 |
| V1-16B | 主数据适配、标准模板、映射、差异审核、受控建档与增量导入 | 只处理主数据，禁止创建正式库存数量 |
| V1-16C | 私有上传、批次清洗、实物盘点清单、差异核对与冻结 | 只处理预览、审核与证据，全程无库存数量变化 |
| V1-17 | 正式期初专项签核、原生入账、失败续跑与逐桶核对 | 依签核版本通过受控原生流程入账 |

## 架构兼容性评审

以下评审以 PR #29 合入后的 main `1ed9e04a96a8ead29e6a17bc71e7affb97235306` 为基线。

| 现有实现 | 差距及拟议工程处理 |
| --- | --- |
| `catalog/persistence.py` 使用统一的 `HP V1 Catalog Maintainer` 写权限。 | 评审并落实产品、参数维护的独立服务端授权，覆盖从产品编辑打开的受控窗口。 |
| 规格和 SKU 创建服务由调用方提供编码，普通规格编辑当前可以变更规格编码。 | 统一分配新编码，防并发重复及号码再分配，普通编辑保持规格编码固定。 |
| 库存单位及精度位于 SKU 层，创建校验现有 SKU 配置。 | 增加规格层业务约束及同规格一致性校验，评审有单位差异的旧数据如何安全升级。 |
| SKU 已支持 `LEGACY` 类型标识。 | 补充规格级历史标识、迁移来源映射和授权搜索，保持领域 ID 稳定。 |
| 默认以 SKU Code 作为新建原生 Item 的初始编码，已有显式 Item 关联。 | 评估为新建记录采用独立稳定的内部标识。保留已验证的既有 Item 映射，避免无必要重命名。具体做法由架构评审决定。 |
| V1-06 的批次规范化核心基本符合 B03，现有记录可带候选策略版本。 | 优先复用，评估正式策略升级、既有键和映射兼容、历史原文及异常审核，保留旧版本的历史含义。 |
| V1-15 提供私有导出存储及受控下载。 | 复用可用技术基础，另行设计安全上传、期初审核及跨仓文件授权。 |
| V1-15 隔离产品技术字段、搜索、导出及撤权后的文件访问。 | 迁移入口、映射搜索、预览与文件复用同一授权边界，验证聚合、筛选、导出、下载及撤权路径。 |
